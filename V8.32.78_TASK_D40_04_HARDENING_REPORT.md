## 1. Initial Implementation Findings (Baseline Inspection)

Prior to modifying any source code, an exhaustive inspection of the live source files, tests, and audit reports (`V8.32.77`, `V8.32.76`, `PILOT_001_GATEWAY_ADAPTER.md`) was conducted. This established the actual source-code baseline and separated concrete evidence from report claims:

1. **INFO-01 Model Discovery Vulnerability (`pilot-validator.js:54-62`):**
   - *Claim:* Request validation ensures model availability before dispatch.
   - *Actual Source Code:* Line 54 inspected `if (Array.isArray(availableModels) && availableModels.length > 0)`. When LM Studio was offline or unreachable, `fetchAvailableModels()` returned `[]`. Because `length > 0` evaluated to `false`, the validator bypassed model verification entirely and allowed request admission, deferring the network failure to the downstream Axios call.
   - *Finding:* A request could pass schema validation even when LM Studio model availability was completely unconfirmed or offline.

2. **Middleware Registration Order & Authentication (`gateway-server.js:20` vs `gateway-server.js:87-94`):**
   - *Claim:* V8.32.77 executive summary stated *"Pre-shared key (PSK) authentication is executed prior to any payload parsing"*.
   - *Actual Source Code:* Line 20 executed `app.use(express.json({ limit: '1mb' }))` globally at application startup. The route handler at line 282 attached `authMiddleware` as route middleware (`app.post('/v1/pilot/inference', authMiddleware, ...)`). Express executes global middleware before route-level middleware.
   - *Finding:* Any incoming HTTP request—regardless of authentication—had its body parsed, buffered, and decoded into JSON before `authMiddleware` was ever invoked. An unauthenticated client submitting malformed JSON received HTTP 400 (`SyntaxError: Unexpected token...`) from `body-parser` rather than HTTP 401 Unauthorized. Large or malicious payloads could consume memory and CPU without credentials.

3. **Filesystem Boundary & Fixture Path Sanitization (`pilot-001-runner.js:66-77`):**
   - *Claim:* Complete isolation from production databases and archives.
   - *Actual Source Code:* The check only looked at naive substring presence: `lower.includes('whatsapp') || lower.includes('.db') || lower.includes('forensics')`. The path was resolved via `path.resolve(process.cwd(), args[fixtureIndex + 1])`.
   - *Finding:* Arbitrary external files could be read if their path did not contain those three substrings (e.g., `fixtures/pilot/../../package.json`, system configuration files). Traversal sequences and symlinks/junctions pointing outside the directory were not guarded against canonical realpath resolution.

4. **Response Provenance (`pilot-response-schema.json`, `gateway-server.js:388-456`):**
   - *Actual Source Code:* The gateway only checked JSON structure via Ajv schema and attempted `JSON.parse()` on candidate text.
   - *Finding:* The pipeline validated structural conformity but had zero verifiable provenance linking claims back to exact source text offsets, message identifiers, or human review status.

## 2. Exact Corrections Made

All changes were applied with minimal surface area, strict change control, and zero breakage of existing legacy interfaces.

### 2.1 Resolution of INFO-01: Model Availability Guard
- **File:** `orchestration/gateway/pilot-validator.js`
- **Correction:** Replaced the permissive `length > 0` condition with a mandatory availability requirement:
  ```javascript
  // 4. Model availability validation:
  // Reject if LM Studio model discovery failed, returned empty, or model is absent
  if (!Array.isArray(availableModels) || availableModels.length === 0) {
      return {
          isValid: false,
          errorCode: 'MODEL_UNAVAILABLE',
          message: 'LM Studio model discovery failed or no models are currently available.'
      };
  }

  if (!availableModels.includes(body.model)) {
      return {
          isValid: false,
          errorCode: 'MODEL_UNAVAILABLE',
          message: `Requested model '${body.model}' is not currently loaded in LM Studio. Available models: [${availableModels.join(', ')}]`
      };
  }
  ```
- **Result:** If LM Studio model discovery fails, times out, or returns an empty model list, the request is immediately rejected at the validation layer with `503 MODEL_UNAVAILABLE` prior to inference dispatch.

### 2.2 Verification & Hardening of Authentication Order
- **File:** `orchestration/gateway/gateway-server.js`
- **Correction:** Removed the global `app.use(express.json())` call before authentication. Defined `jsonParser = express.json({ limit: '1mb' })` and attached `authMiddleware` before `jsonParser` on both `/v1/pilot/inference` and `/v1/inference`:
  ```javascript
  const authMiddleware = requireAuth ? createInternalAuthMiddleware() : (req, res, next) => next();
  const jsonParser = express.json({ limit: '1mb' });

  // Route 1 (Legacy):
  app.post('/v1/inference', authMiddleware, jsonParser, async (req, res) => { ... });

  // Route 2 (Pilot Contract):
  app.post('/v1/pilot/inference', authMiddleware, jsonParser, async (req, res) => { ... });
  ```
- **Result:** Unauthenticated requests are intercepted and terminated with HTTP 401 Unauthorized before any JSON parsing or raw body buffering occurs.

### 2.3 Filesystem Boundary Hardening
- **File:** `pilot-001-runner.js`
- **Correction:** 
  1. Default execution continues to strictly use the hardcoded synthetic fixture.
  2. If `--fixture` is specified, the runner restricts input strictly to an approved dedicated directory (`fixtures/pilot/`) using `path.basename()`.
  3. Uses `fs.realpathSync()` to resolve canonical paths and explicitly guards against symlink/junction escape (`path.relative(realApprovedDir, realCandidatePath).startsWith('..')`).
  4. Requires the `.json` extension.
  5. Retains case-insensitive substring blocks for `whatsapp`, `.db`, `forensics`, and `.sqlite`.
  6. Terminates immediately with exit code 2 on any deviation.

## 4. Middleware Execution Order Verification

### Actual Middleware Chain (Verified via Source & Automated Tests)

1. Client opens TCP socket to `http://127.0.0.1:4000`.
2. Express matches route `POST /v1/pilot/inference`.
3. First handler invoked: `authMiddleware` (`createInternalAuthMiddleware()`).
   - Checks `x-internal-service-token` or `Authorization: Bearer <psk>`.
   - Compares SHA-256 digests via `crypto.timingSafeEqual`.
   - **If unauthenticated:** Immediately returns HTTP 401 with `{ error: 'Unauthorized: ...' }`. **Request ends here.** No request body bytes are parsed as JSON.
4. Second handler invoked: `jsonParser` (`express.json({ limit: '1mb' })`).
   - Only runs for authenticated callers.
   - Buffers and parses JSON. Rejects malformed JSON with HTTP 400 or oversized (>1MB) payloads with HTTP 413.
5. Third handler invoked: Route handler `async (req, res) => ...`.

### Verification Evidence Matrix:

| Test Scenario | Credentials | Payload | Expected Status | Actual Status | Middleware Observed |
| :--- | :--- | :--- | :--- | :--- | :--- |
| Missing PSK | None | Valid JSON | 401 | 401 | Intercepted at `authMiddleware` |
| Incorrect PSK | Invalid | Valid JSON | 401 | 401 | Intercepted at `authMiddleware` |
| Malformed JSON without PSK | None | Broken JSON (`{ broken`) | 401 | 401 | Intercepted at `authMiddleware` before `jsonParser` |

## 5. Model-Availability Behavior Verification

The model availability check now enforces zero-tolerance validation:

1. **LM Studio Offline:**
   - `fetchAvailableModels()` catches connection errors and returns `[]`.
   - `validatePilotRequest()` checks `!Array.isArray(availableModels) || availableModels.length === 0`.
   - Returns `{ isValid: false, errorCode: 'MODEL_UNAVAILABLE' }`.
   - Gateway returns HTTP 503 with standard error envelope before dispatch.
2. **Empty Model List:**
   - If LM Studio is running but has no models loaded, returns `[]`.
   - Rejected identically with HTTP 503 `MODEL_UNAVAILABLE`.
3. **Requested Model Absent:**
   - If requested model is not in the array returned by LM Studio, rejected with HTTP 503 `MODEL_UNAVAILABLE`.
4. **Model Discovery Timeout:**
   - Axios request to `/v1/models` times out after 3,000 ms.
   - Caught in `catch` block, returns `[]`.
   - Request rejected with HTTP 503 `MODEL_UNAVAILABLE`.
5. **No Fallback:**
   - Gateway never silently redirects to `local-model` or any other alias.

## 7. Response Provenance Contract Proposal

### 7.1 Problem Statement
The current PILOT-001 response envelope guarantees that the LLM output conforms to JSON Schema (`result.text` and `result.parsed_json`), but it does not guarantee **factual provenance** or **truth grounding**. A response can be schema-valid while being an ungrounded hallucination or paraphrase.

### 7.2 Three Distinct Acceptance States
To prevent conflating schema conformance with factual correctness, three tiers are established:

1. **Schema-Valid Output:** The JSON structure strictly conforms to Draft 2020-12 schema rules (types, formats, non-null result).
2. **Source-Validated Output:** Every extracted assertion is programmatically linked to an exact substring in the source message (`exact_quote`) with verifiable character start/end offsets. Paraphrases are rejected.
3. **Human-Approved Output:** An authorized human operator has inspected the source text, the extracted quote, and the structured entity, and explicitly marked it approved.

### 7.3 Minimum Provenance Schema Specification (`pilot-provenance-contract-v1`)

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "PilotProvenanceContract",
  "type": "object",
  "required": [
    "extraction_id",
    "source_message_id",
    "conversation_id",
    "model_id",
    "request_id",
    "processing_timestamp",
    "verifiable_claims",
    "human_review"
  ],
  "properties": {
    "extraction_id": { "type": "string", "pattern": "^ext-[A-Za-z0-9_-]{8,32}$" },
    "source_message_id": { "type": "string", "pattern": "^msg-[A-Za-z0-9_-]{8,64}$" },
    "conversation_id": { "type": "string", "pattern": "^conv-[A-Za-z0-9_-]{8,64}$" },
    "model_id": { "type": "string" },
    "request_id": { "type": "string" },
    "processing_timestamp": { "type": "string", "format": "date-time" },
    "verifiable_claims": {
      "type": "array",
      "minItems": 1,
      "items": {
        "type": "object",
        "required": [
          "claim_id",
          "field_name",
          "extracted_value",
          "exact_quote",
          "source_char_offset"
        ],
        "properties": {
          "claim_id": { "type": "string" },
          "field_name": { "type": "string" },
          "extracted_value": {},
          "exact_quote": {
            "type": "string",
            "minLength": 1,
            "description": "Must match verbatim against source message text. Paraphrases strictly invalid."
          },
          "source_char_offset": {
            "type": "object",
            "required": ["start", "end"],
            "properties": {
              "start": { "type": "integer", "minimum": 0 },
              "end": { "type": "integer", "minimum": 0 }
            }
          }
        },
        "additionalProperties": false
      }
    },
    "human_review": {
      "type": "object",
      "required": ["status", "reviewed_by", "reviewed_at", "notes"],
      "properties": {
        "status": {
          "type": "string",
          "enum": ["PENDING_REVIEW", "APPROVED", "REJECTED", "CORRECTED"]
        },
        "reviewed_by": { "type": ["string", "null"] },

        "notes": { "type": ["string", "null"] }
      },
      "additionalProperties": false
    }
  },
  "additionalProperties": false
}
```

## 9. Remaining Risks

1. **Extraction Grounding Risk:** As detailed in Section 7, while the gateway enforces schema conformance and auth boundaries, the pilot runner does not yet enforce source quote verification. When a future real WhatsApp pilot is authorized, the extractor must incorporate verbatim quote offset checking before human review.
2. **Single-Node Concurrency Saturation:** The local gateway enforces `GATEWAY_MAX_CONCURRENCY=2` (tested with 1 slot in unit tests). High concurrency bursts will return HTTP 429. Callers must handle backoff cleanly.
3. **LM Studio Hardware Dependency:** LM Studio is bound locally to GPU memory. If the model is unloaded by the user outside the agent's control, requests will fail with `503 MODEL_UNAVAILABLE` until reloaded.
