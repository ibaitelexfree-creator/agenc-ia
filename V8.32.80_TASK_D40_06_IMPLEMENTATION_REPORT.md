## 1. Initial Findings & Blocker Baseline

Inspection of `V8.32.79_TASK_D40_05_INDEPENDENT_ACCEPTANCE_AUDIT.md` established the five blockers addressed in this task:

1. **SEC-01 (CRITICAL - Provenance Verification Absent from Runtime):**
   The provenance contract existed purely as markdown documentation. Zero programmatic validation verified that extracted quotes matched source messages verbatim or checked character offset bounds.
2. **SEC-02 (CRITICAL - Lack of Review Separation & Risk of Model Self-Approval):**
   The proposed extraction contract contained review fields (`human_review.status`). If an LLM is requested to produce JSON adhering to this schema, it can output `"status": "APPROVED"`. There was no separation between model generation and trusted review state.
3. **SEC-03 (HIGH - Arbitrary Fixture Path & Hardlink Vulnerability):**
   `pilot-001-runner.js` accepted `--fixture <path>`, which used `path.basename()` and `fs.realpathSync()`. This remained vulnerable to NTFS hardlinks originating outside the approved directory and permitted arbitrary file arguments.
4. **SEC-04 (HIGH - Identifier Format Incompatibility):**
   The proposed schema enforced arbitrary regex patterns (`^msg-[A-Za-z0-9_-]{8,64}$`). Real WhatsApp databases use SQLite integer rowids and WhatsApp JIDs (`[phone]@s.whatsapp.net`, `[group]@g.us`).
5. **SEC-05 (MEDIUM - Unspecified Character Offset Encoding & Missing Invariants):**
   Character offset encoding (UTF-16 code units vs code points vs UTF-8 bytes) was undefined, and invariants (`start >= 0`, `end > start`, `end <= source_text.length`) were not enforced.

## 4. Technical Implementation Details

### 4.1 SEC-01 & SEC-05: Executable Provenance Verification Engine (`provenance-verifier.js`)
- **Exact Quotation Match:** Quotes must match verbatim in `source_text`. No trimming, case-folding, normalization, or paraphrasing is performed.
- **Offset Standard:** Explicitly standardized on **UTF-16 code units with exclusive end positions** (`source_text.substring(start, end)`), matching standard JavaScript string indexing.
- **Invariant Rules Enforced:**
  - `start >= 0`
  - `end > start`
  - `end <= source_text.length`
  - `source_text.substring(start, end) === exact_quote`
- **Ambiguity Detection:** `findQuotationOccurrences()` scans all occurrences. If a quote occurs more than once in `source_text` and no disambiguating offsets are provided, the engine rejects with `AMBIGUOUS_QUOTATION`.
- **Source Integrity:** `computeSourceHash(sourceText)` computes SHA-256 over raw source text encoded as UTF-8. Returns `SOURCE_HASH_MISMATCH` if input hash does not match computed digest.
- **Separation of Concepts:** The verifier returns `is_grounded: true` and `code: 'SOURCE_GROUNDED'`. It never assigns or infers `HUMAN_APPROVED`.

### 4.2 SEC-02: Separation of Extraction & Human Review Planes (`review-manager.js` & `pilot-candidate-extraction-schema.json`)
- **Strict Candidate Contract:** `pilot-candidate-extraction-schema.json` allows the model to output only `extraction_id`, `source_message_id`, `conversation_id`, and `verifiable_claims` (`claim_id`, `field_name`, `extracted_value`, `exact_quote`, optional `source_char_offset`).
- **Prohibited Model Injection:** Any attempt by the model to return `status`, `human_review`, `reviewer_id`, `reviewed_by`, `reviewed_at`, `approved`, etc. triggers an immediate security violation.
- **Application-Managed Review State:** `createPendingReviewRecord()` runs inside trusted application logic. It verifies provenance, computes source hash, and constructs the review envelope with `human_review.status = 'PENDING_REVIEW'`.

### 4.3 SEC-04: Opaque Identifier Representation (`validateSourceIdentifier`)
- Arbitrary `^msg-` and `^conv-` prefixes were completely eliminated.
- Identifiers are validated as opaque typed objects:
  - SQLite 64-bit integers: Can be passed as integer, canonical digit string, or BigInt to prevent JavaScript 64-bit float precision loss. Normalized to `{ type: "integer", value: "<canonical_digits>" }`.
  - WhatsApp JIDs & text IDs: Handled as `{ type: "text", value: "<exact_string>" }`.

### 4.4 SEC-03: Deprecation of Arbitrary Fixture Paths (`synthetic-fixtures.js` & `pilot-001-runner.js`)
- Removed `--fixture <path>` completely. Any attempt to use `--fixture` exits with status 2: `FATAL SECURITY VIOLATION: --fixture <path> has been permanently deprecated`.
- Replaced with `--fixture-id <ID>`, backed by an in-memory registry of approved synthetic fixtures (`SYNTHETIC_001`, `SYNTHETIC_002`) with immutable payloads and SHA-256 hashes.
- Traversal sequences (`../`, `..\\`), absolute paths (`C:\...`, `/etc/...`), and arbitrary file references are cleanly rejected by key lookup.
