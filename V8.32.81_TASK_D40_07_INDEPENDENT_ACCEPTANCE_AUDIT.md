```
         ├── Validates validatePilotResponse()

```

### 3.2 Identification of Critical Integration Disconnection

The trace reveals an explicit architectural disconnection:
1. `orchestration/gateway/provenance-verifier.js` is imported **only** by `review-manager.js` and `provenance-verifier.test.js`.
2. `orchestration/gateway/review-manager.js` is imported **only** by `provenance-verifier.test.js`.
3. Neither `gateway-server.js` nor `pilot-001-runner.js` imports or invokes `createPendingReviewRecord()`, `verifyExtractionProvenance()`, or `validateCandidateExtraction()`.
4. Therefore, when LM Studio produces a JSON payload (e.g., matching or failing candidate extraction), **no provenance check is performed in the Gateway runtime before the response is delivered to the client**.
5. An untrusted component or upstream caller can supply a candidate extraction with an invalid quote or mismatched source text, and the Gateway will return HTTP 200 `SUCCESS` without provenance verification.

**Conclusion for Integration:** While the unit functions work as specified in isolation, the **integration into the execution pipeline is incomplete**. This prevents awarding `CLOSED` to `SEC-01` and `SEC-02`.

## 4. Adversarial Findings Analysis (SEC-01 to SEC-05)

### 4.1 SEC-01: Provenance Verification Engine
- **Evaluation Status:** **PARTIALLY CLOSED**
- **Executable Evidence Verified:**
  1. *Exact Quotation Matching:* `findQuotationOccurrences()` and `source_text.substring(start, end) === quote` perform verbatim matching without trimming, normalization, or case-folding. Paraphrases are rejected with `UNGROUNDED_EXTRACTION`.
  2. *Character Offset Conventions:* Operates strictly on UTF-16 code units with exclusive end offsets.
  3. *Boundary Invariants:* Out-of-bounds, negative, or inverted offsets (`start >= end`) are rejected with `INVALID_OFFSETS`.
  4. *Quotation Ambiguity:* When a quote appears multiple times and offsets are not provided, it is rejected with `AMBIGUOUS_QUOTATION`.
  5. *Source Hash Integrity:* UTF-8 SHA-256 hash check ensures text has not mutated.
- **Vulnerability / Bypass Analysis:**
  - *Bypass 1 (Gateway Runtime Bypass):* Because `gateway-server.js` does not call `verifyExtractionProvenance`, any model response is accepted as long as it parses as JSON and fits `pilot-response-schema.json`.
  - *Bypass 2 (Source Text / Hash Co-Supplied):* In `verifyExtractionProvenance`, if an untrusted caller supplies both `source_text` and `source_hash`, the verifier checks `actualHash === source_hash`. While cryptographic consistency is verified, this does **not** prove that `source_text` originated from the actual WhatsApp message database. Authenticating the source itself requires an immutable database provenance link (e.g., retrieving `source_text` directly by database primary key rather than accepting it from an untrusted client).

### 4.2 SEC-02: Human Review Separation
- **Evaluation Status:** **CLOSED** *(Isolated Plane)* / **BLOCKER** *(Integration & Auth)*
- **Executable Evidence Verified:**
  1. `FORBIDDEN_MODEL_FIELDS` rejects model outputs attempting to supply `human_review`, `review_status`, `approved`, `reviewer_id`, `reviewed_by`, or `status`.
  2. `createPendingReviewRecord()` enforces `human_review.status = 'PENDING_REVIEW'`, `reviewed_by = null`, `reviewed_at = null`, `reviewer_signature = null`.
  3. The model output is strictly confined to `pilot-candidate-extraction-schema.json` (claims, quotes, extracted values).
- **Vulnerability / Bypass Analysis:**
  - *No Downstream Consumer or Store:* The review record is constructed as an in-memory object during tests, but no persistence store (database table or immutable append-only ledger) currently stores these pending records.
  - *Lack of Authenticated Review Subsystem:* There is currently no mechanism or API endpoint for an authenticated human reviewer to review, sign, or transition a record from `PENDING_REVIEW` to `APPROVED`.

### 4.3 SEC-03: Fixture Security
- **Evaluation Status:** **CLOSED**
- **Executable Evidence Verified:**
  1. `pilot-001-runner.js` rejects `--fixture <path>` with exit code 2 and explicit security warning.
  2. The runner only accepts `--fixture-id <ID>`.
  3. `getSyntheticFixture()` matches against `SYNTHETIC_FIXTURES` keys. Path traversal (`../`, `..\\`), absolute paths (`C:\...`), and arbitrary IDs are rejected with `isValid: false`.
  4. Deep cloning (`JSON.parse(JSON.stringify(entry.payload))`) guarantees that mutations to returned payload instances do not alter the master in-memory fixture registry.
  5. Tested adversarially in `fixture-security.test.js` (10 passing adversarial tests).

### 4.4 SEC-04: Identifier Safety
- **Evaluation Status:** **CLOSED**
- **Executable Evidence Verified:**
  1. `validateSourceIdentifier()` handles SQLite integer IDs passed as `number`, `bigint`, or canonical numeric `string`.
  2. Avoids JavaScript IEEE-754 64-bit float precision truncation for 64-bit SQLite integer rowids by storing canonical decimal strings (`{ type: "integer", value: "9007199254740993" }`).
  3. Supports WhatsApp JIDs (`1234567890@s.whatsapp.net`, `12036302@g.us`) without inventing artificial prefixes.
  4. Rejects null, undefined, empty strings, floats, and unsupported types.

### 4.5 SEC-05: Offset and Source Integrity
- **Evaluation Status:** **CLOSED**
- **Executable Evidence Verified:**
  1. Offset standard is strictly documented and enforced: UTF-16 code units, 0-indexed, exclusive end positions.
  2. Verified across Spanish accented text (`á, é, í, ó, ú, ñ, ¿, ¡`), Thai combining vowels/tone marks, emojis (surrogate pairs taking 2 code units), and multiline strings with newlines (`\n`).
  3. Source text hashing uses UTF-8 SHA-256 digest comparison.

## 6. Audit Assumptions & Potential Attack Vectors

1. **Untrusted Grounding Anchor (Source Text Tampering):**
   If a model output is accompanied by source text provided by the model or by an unverified intermediary, the verifier will confirm that the quote matches the *provided* text, but not that the provided text matches the immutable forensic archive.
   *Mitigation Requirement:* The Gateway or Extraction Worker must fetch the source text directly from the immutable message storage using the verified `source_message_id`, rather than allowing the extraction payload to supply its own source text.
2. **Gateway Response Contract vs Candidate Extraction Contract:**
   Currently, `gateway-server.js` validates outgoing responses against `pilot-response-schema.json`, which permits arbitrary JSON in `result.parsed_json`. There is no schema validation enforcing that `result.parsed_json` complies with `pilot-candidate-extraction-schema.json` when extraction tasks are performed.
3. **Absence of Operator Review Store:**
   The `createPendingReviewRecord()` function produces a valid review envelope, but there is no persistence adapter to write this record to a database, message queue, or review queue.

## 7. Remaining Blockers for Production / Real WhatsApp Pilot

The following blockers must be addressed prior to authorizing any pilot execution:

1. **BLOCKER-01 (Gateway Extraction Pipeline Integration):**
   Integrate `review-manager.js` into the extraction dispatch flow. When an extraction task is processed, the Gateway or downstream pipeline must automatically validate the output against `pilot-candidate-extraction-schema.json`, run `verifyExtractionProvenance()`, and construct the `PENDING_REVIEW` envelope.
2. **BLOCKER-02 (Immutable Source Retrieval Gate):**
   Source text for provenance verification must be retrieved by the trusted application from the storage layer using the source identifier, preventing untrusted callers from fabricating source text.
3. **BLOCKER-03 (Human Review Authentication Subsystem):**
   An authenticated operator review workflow and signature mechanism must be implemented before extractions can ever be marked `APPROVED`.
4. **BLOCKER-04 (Mocking Infrastructure for LM Studio in CI/CD):**
   Refactor `pilot-contract-adapter.test.js` to use an in-process mock HTTP server for LM Studio so that the full regression suite can run deterministically without requiring a live model server.
