## 2. Phase 1 — Inspection Baseline Report

### 2.1 Implemented vs. Documented Analysis
- **Gateway Server (`gateway-server.js`):**
  - *Actually Implemented:* Single-turn inference at `/v1/inference` accepting `{ prompt, system_prompt, model, temperature, max_tokens, timeout_ms }`, concurrency limiting, audit phase logging, health endpoint with LM Studio ping.
  - *Documented in PILOT Contract but Missing:* Envelope fields (`task_id`, `agent_id`, `output_schema_version`, `messages[]`), JSON Schema validation, structured JSON parsing into `result.parsed_json`, standard error envelopes.

  - *Actually Implemented:* Timing-safe SHA-256 pre-shared key validation (`crypto.timingSafeEqual`), minimum 32-character entropy enforcement, support for `x-internal-service-token` and `Bearer` headers.

- **Dependencies:**
  - `ajv` (v8.18.0) and `ajv-formats` (v3.0.1) were present in `orchestration/node_modules`. Because the contract uses JSON Schema Draft 2020-12, `ajv/dist/2020.js` was required for full standard compliance.
- **Backward Compatibility:**
  - Implementing the pilot interface on a dedicated route (`POST /v1/pilot/inference`) leaves `POST /v1/inference` fully intact and backward-compatible with legacy callers.

## 3. Phase 2 — JSON Schema Validation Architecture

Implemented in `orchestration/gateway/pilot-validator.js`:
- Uses `Ajv2020` with `addFormats` to validate draft 2020-12 schemas.
- **Request Rules:**
  - Fields `task_id`, `agent_id`, `request_id`, `model`, `temperature`, `messages`, `output_schema_version` are strictly required.
  - `additionalProperties: false` rejects injected or unapproved fields.
  - `messages` array length is bounded `[1, 50]`.
  - Content length per message bounded `[1, 8192]`.
  - **Aggregate content length** across all messages is validated in JavaScript to ensure total <= 8,192 characters.
  - Generic alias `local-model` is explicitly rejected. Models must match an actively loaded LM Studio identifier.
- **Response Rules:**
  - Mutually exclusive condition enforced via `allOf` conditional schemas:
    - If `status == "SUCCESS"`, `result` must be an object and `error` must be `null`.
    - If `status != "SUCCESS"`, `result` must be `null` and `error` must be an object.
  - `execution_timestamp` validated as ISO 8601 UTC date-time string.

## 4. Phase 3 — Gateway Adapter Implementation

Implemented in `orchestration/gateway/gateway-server.js` at route `POST /v1/pilot/inference`:
- Enforces `internal-auth` middleware before request parsing.
- Queries active LM Studio models dynamically to validate target model availability.
- Enforces concurrency semaphore ceiling (`GATEWAY_MAX_CONCURRENCY`).
- Adapts `messages[]` to LM Studio `/v1/chat/completions`.
- Parses structured JSON output from responses (including raw JSON or markdown code-fences).
- Emits structured pilot audit events:
  - `PILOT_PHASE_1_RECEIVED`
  - `PILOT_PHASE_2_ADMITTED`
  - `PILOT_PHASE_3_DISPATCHED_TO_LM_STUDIO`
  - `PILOT_PHASE_4_RESPONSE_RECEIVED`
  - `PILOT_PHASE_5_COMPLETED`
- Preserves correlation IDs (`request_id`, `task_id`, `agent_id`) in all response branches.

## 5. Phase 4 — Supervised Synthetic Runner

Created `pilot-001-runner.js`:
- **Operator Gate:** Blocks execution unless explicitly run with `--execute`.
- **Synthetic Boundary Enforcement:** Blocks any execution referencing WhatsApp archives, SQLite files, or forensics folders.
- **Single-Shot:** Dispatches exactly one HTTP request per invocation with zero retries.
- Displays full pre-dispatch request envelope and post-dispatch response envelope.
- Validates response envelope against `pilot-response-schema.json`.
- Exits with distinct non-zero exit codes on any validation or transport failure.
